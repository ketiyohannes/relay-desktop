# Relay desktop

Electron workspace with a project/session library, streaming conversation, expandable tool calls, and an ordered code timeline. The interface follows [T3 Code's workspace configuration](https://github.com/pingdotgg/t3code/tree/main/apps/web/src): neutral surfaces, compact sidebar rows, full-width conversation content with consistent gutters, and account controls inside a padded composer. The title-bar theme selector offers Light, Dark, and System, saving the choice across launches. System follows OS appearance changes automatically. The project sidebar can be collapsed, with its visibility also saved.

Icons are the regular-weight SVGs from `@phosphor-icons/core`, pinned to 2.1.1. The selected assets and MIT license are included locally in `ui/icons` so Electron and the browser preview work offline. Regenerate them with `npm run icons --workspace packages/desktop`.

Both sidebars can be collapsed using the title-bar buttons or resized by dragging their dividers. Focus a divider and use arrow keys to resize, or Home/End to choose its minimum/maximum width. Widths and visibility persist; narrow windows clamp widths to preserve space for the conversation. The inspector offers Timeline, Changes, Files, and Code tabs. Its history control defaults to the working tree; Files opens full file contents in Code, while Changes shows the selected file's diff. Before/after views retain deleted files. The working-tree view reads saved files directly, including before the first prompt. Search filters the file list. Historical selections use recorded Git snapshots. Unsaved editor buffers are not visible. Line-number tooltips identify their originating snapshot; click a historical line number to inspect that checkpoint.

## Run

Use Node 22.19 or newer. From the repository root:

```sh
npm install --ignore-scripts
# Run this reviewed lifecycle script only after explicitly authorizing it:
node node_modules/electron/install.js
npm run desktop
```

`RELAY_NODE_PATH` selects the Node executable for the agent child process. On this machine the default Volta Node is too old; use `RELAY_NODE_PATH=/opt/homebrew/bin/node npm run desktop`. The development launcher bundles only the Electron main/preload entry points into ignored `.runtime/` files; runtime packages execute from source through the existing source resolver.

`RELAY_DATA_DIR` optionally selects an isolated data directory for desktop QA. Normal launches store data under the OS application-data directory's `Relay` folder.

For a browser-only design preview: `npm run preview --workspace packages/desktop` and open `http://127.0.0.1:4318`. The preview cannot access folders or providers.

## Accounts and sessions

The composer has separate account and model dropdowns. The account dropdown shows provider labels, fallback order, remaining usage, and connection/management actions. Click the model name to search authenticated models across every saved account, grouped by account and provider. Search accepts account names, model names, IDs, and descriptions. Selecting a model also selects its account in the same session. Unavailable profiles show their own status without hiding other accounts. Pi/Codex uses the existing `ModelRuntime` catalog and credential adapters. Claude uses the Agent SDK's `supportedModels()` and `accountInfo()` control requests with an empty input stream; discovery sends no model prompt and times out after 20 seconds. Model choices are validated again when selected, recorded in the conversation, and saved per session and per account. Switching accounts restores that account's selection. Stop a running request before changing its model.

Usage meters show provider-reported **remaining percentages**, reset times, and the last check time, rather than estimated token counts. Five-hour and weekly windows appear when available, including model-specific buckets. Codex Pro variants display **No 5-hour limit** and omit that meter; Standard Business retains its reported windows, following [OpenAI's pricing documentation](https://learn.chatgpt.com/docs/pricing). API-key accounts have no subscription meter. Missing data remains unavailable and failed refreshes clear previous percentages. Reset times do not imply a refill until confirmed by the provider.

Usage loads for the active account on startup and after a run, and refreshes every minute while visible. Opening account controls also checks other profiles; the refresh button bypasses the one-minute cache. Reads are coalesced per profile and time out after 22 seconds without blocking model selection. Codex uses the [app-server account rate-limit API](https://developers.openai.com/codex/app-server/) with experimental external-token authentication in a temporary, isolated `CODEX_HOME`. This requires an installed Codex CLI: Relay checks `RELAY_CODEX_PATH`, the standalone `~/.local/bin/codex` installation, then PATH. OAuth refresh reuses Pi's existing runtime and credential adapters. Claude uses the pinned Agent SDK's experimental usage metadata method with transcript scanning disabled. Neither reader sends a model prompt; unsupported CLI/SDK behavior produces an unavailable meter without interrupting the session.

**Accounts** has **Connected**, **Add account**, and **Existing profile** tabs. Connected accounts can be selected, edited, checked for credential metadata, and moved earlier or later in fallback order. A successful credential check does not prove remaining quota or that a token has not been revoked. Existing profiles are checked before saving. **Create an account** opens the provider's official signup/login page; after registration, return to Relay and use **Sign in** to authorize the new account. Relay does not maintain a separate registration service.

In **Accounts**, enter a display name and choose **Sign in with Codex** or **Sign in with Claude**. Codex offers browser or device-code authorization and a manual redirect fallback. Claude launches the official SDK-bundled `claude auth login --claudeai` flow. Complete authorization in your system browser; Relay saves the account automatically and selects it when the current session has no account. Repeat to add separate subscriptions. Cancel or close Accounts to stop an unfinished login. Sign-in expires after 15 minutes. Failed/cancelled attempts remove only their newly created profile directory.

Managed credentials live in isolated provider profiles under `userData/sessions/accounts`, outside the renderer. Claude may use its OS credential store. Passwords are entered on provider pages, never in Relay. Existing-profile connection remains available under **Connect an existing profile**.

Open a project through the themed folder browser: enter a path, navigate folders, filter with search, and select **Open folder**. **Open in Finder** is an optional bottom action. Then use **Accounts** to connect authenticated profiles. Claude uses the Claude Agent SDK; Pi uses the existing agent core, credential refresh, model runtime, and coding tools. For Claude, point to a Claude config directory. Use **Use Codex login** to connect the native `~/.codex` ChatGPT login directly. Relay adapts it to Pi's `openai-codex` provider without copying credentials. OAuth refresh writes back to that original profile while preserving unrelated metadata. Custom Codex profile directories use the same credential format. **Use Pi profile** connects a Pi directory containing `auth.json` and optional `models.json`. **Load profile models** supplies available model IDs and stored-auth metadata. Account rows support editing and changing fallback order. A blank directory uses the engine's default profile. Separate accounts need separately authenticated directories; Relay does not log accounts out or copy credentials; the engine refreshes credentials in their original profile when needed. Explicit Claude profile selection suppresses inherited API-key/token overrides.

Select an account in the composer. With **Auto switch** enabled, confirmed subscription/quota exhaustion tries remaining profiles in configuration order, once each. Each fallback's credentials and selected model are checked first; unavailable candidates are skipped with an inline explanation. Model choices remain independent across accounts and providers. Claude's structured subscription rejections also trigger recovery if the SDK stream terminates without a final result. Allowed overage warnings alone do not trigger rotation. Generic HTTP 429s, authentication failures, timeouts, and context-window errors do not trigger rotation. One run is allowed across the desktop so concurrent sessions cannot misattribute project edits. You can browse another session while a run continues, then stop the active run with **Stop run**. Switching the active account during a run interrupts the old engine, captures its settled state, and continues from the shared history with the new account. Stop and disabling automatic switching remain authoritative during fallback discovery. Accounts are retried on later runs; Relay does not infer a quota reset time.

Relay owns the shared conversation/action ledger. Claude's native transcript is mirrored as opaque SDK entries and used for explicit session resume across profile directories. Pi receives the shared conversation and completed tool ledger as context each turn. Crossing engines supplies that context to Claude as well. This preserves Relay session identity; it is not a conversion of native Pi messages into a Claude transcript. Completed tool calls are recorded before account recovery; recovery sends a continuation request, rather than rerunning the original tool batch. The model still decides future tool calls, so inspect the recorded effects when a request is interrupted.

Credentials remain in each engine's managed or existing profile. Relay metadata/transcripts are local files under Electron's `userData/sessions` directory, with restrictive file modes. Claude SDK permission requests and Pi tools use a themed approval dialog. Choose **Allow once**, **Allow for this run**, or **Deny**. Per-run approval resets on a new request, cancellation, or manual account selection; it is never saved as a permanent bypass. Startup may read active-account usage metadata; offline tests make no provider requests.

## Timeline and reviews

The explorer adapts the project-history and full-context behavior from the local `timeline-npm` and Neovim `diff-display` projects. **Timeline → Project history** reads ordinary Git commits plus existing `refs/codex-timeline/*` and `refs/relay-timeline/*` recordings. Recorded tree matches group ordered changes under commits; unmatched later recordings appear under **Uncommitted changes**. History refreshes while this view is open. Session activity remains available under **This session**. This integration reads existing Timeline refs; it does not install external hooks.

**Search diffs** searches literal added and removed text, across changed files or the selected file. **Search code** includes unchanged source and removed lines. Results identify the before/after line and open **Changes in context**, which preserves the entire file and interleaves deletions with additions. Searches are case-insensitive and bounded to 200 matching lines, 500 files, 8 MiB of read source, and approximately five seconds; limit/skipped-file notices appear in the search panel. Large single Git reads can exceed the time budget. Project history currently reads up to 2,001 entries per source. File-order annotations for imported history are limited to the most recent 100 recorded events in a group.

Files and snapshot browsing use collapsible directory trees with path search. Expanded snapshots show changed files by default; **All files** exposes the complete tree. **Previous/Next** navigates snapshots. File badges and full-context line-origin buttons identify recorded changes. Saved review notes and AI reviews are visible on their snapshot.

**Edit working file** opens the current UTF-8 source in an editor with syntax-highlighted Preview, explicit Save, and unsaved-edit protection when closing the editor. Saves preserve line endings and permissions, reject stale contents, refuse symlinks/hard links and files outside the project, and record before/after checkpoints when Git is available. Stop an active agent run before saving. Historical files are never overwritten or restored automatically; a deleted working file must be recreated outside this editor. The editor supports existing text files up to 2 MiB. Closing the entire app does not persist unsaved editor drafts.

The middle conversation includes ordered tool calls with command/file summaries, expandable input and readable output, running/completed/failed states, and completion durations. Pi's existing `tool_execution_update` events supply partial output; Claude's `tool_progress` events supply elapsed progress and its hooks supply results. Recorded file changes link to their historical snapshot directly from the conversation. Account/model changes and errors also appear inline. Expanded tool state survives streamed updates.

Projects must be Git repositories for code snapshots. Hidden `refs/relay-timeline/<session-id>` commits capture the entire repository through a temporary index, without touching the user's index, branch, HEAD, or working files. Nonignored untracked files and deletions are included; ignored files are excluded. Pre/post tool boundaries and debounced live filesystem observations produce chronological snapshots. Pi tool execution is sequential; Claude can run parallel tools, so a snapshot is an observed repository state and may contain effects of overlapping tools or external edits.

**Inspect codebase** opens the full historical tree. Changed/deleted files appear first. Switch between the complete before/after file and its diff, with line numbers. Review notes attach to the snapshot and can include `file:line` references. **AI review** runs the selected account against a temporary export of the entire immutable snapshot, with only read/search/list tools available. Edits, shell commands, subagents, and reads outside the exported tree are denied. The review is streamed and persisted against its original snapshot. The temporary export is removed after settlement. Claude reviews use a separate native conversation; they do not replace the coding session resume ID. Git blame tracks the origin checkpoint of retained lines across successive edits.

A file created and deleted in separate tool calls is retained. A change made and undone entirely inside one shell command between observations may not be captured. Very large files can exceed the current 32 MiB Git output limit. Git snapshots remain until their refs are removed explicitly; Relay does not garbage-collect them.

## Verification

Run `npm run check` from the root. Focused offline runtime tests:

```sh
cd packages/coding-agent
node ../../node_modules/vitest/dist/cli.js --run test/desktop/runtime.test.ts test/desktop/claude.test.ts test/desktop/workspace.test.ts test/desktop/login.test.ts test/desktop/accounts.test.ts test/desktop/explorer.test.ts test/desktop/multi-account.test.ts test/desktop/usage.test.ts
```

The focused tests use synthetic engine/SDK/login events and temporary repositories. They cover bounded quota rotation, native Claude continuation, read-only reviews, working-tree browsing and containment, retained add/delete history, nested project folders, line provenance, native Codex credential refresh, cancellation during manual switching, isolated sign-in profiles, prompt cancellation, retries, credential-free UI events, account catalog discovery, session model persistence, and streamed tool states. They consume no paid tokens.

Native Electron QA verified both themes, folder and file search, sidebar geometry, account discovery, actual Codex streaming and write/read tools, persisted timeline capture, and a real read-only snapshot review. Live inference used only a synthetic temporary project with the user's existing Codex login. Additional isolated QA verified grouped account catalogs, account-name model search, account/model selection persistence, project-history browsing, removed-line search navigation, working-file saves, and snapshot review notes. Usage tests cover provider window normalization, cache invalidation, cancellation, subprocess cleanup, and failure redaction. Browser checks exercise the anchored dropdowns, account/model selection, usage refresh, and all three theme modes. Live Codex usage metadata has been verified; live Claude usage/inference and actual multi-account subscription exhaustion have not been exercised. Pi currently sends the shared ledger each turn without automatic compaction; very long histories may need context management.
