# Relay desktop

Electron workspace with a project/session library, streaming conversation, expandable tool calls, and an ordered code timeline. The interface follows [T3 Code's workspace configuration](https://github.com/pingdotgg/t3code/tree/main/apps/web/src): neutral surfaces, compact sidebar rows, full-width conversation content with consistent gutters, and account controls inside a padded composer. The title-bar Settings button opens Light, Dark, and System appearance controls, plus switches for usage meters, the composer account/provider control, and visual effects. Preferences persist across launches. System follows OS appearance changes automatically. Turning off usage meters also stops new automatic usage reads; account management remains available through the sidebar and Settings. Turning off effects disables animations, transitions, shadows, and smooth scrolling. The project sidebar can be collapsed, with its visibility also saved.

The desktop worker uses `packages/core` product services. Codex runs through Codex App Server, Claude through Claude Agent SDK, and other configured models through published pi packages. A local application service owns the durable session registry shared with Relay CLI/terminal. See the [architecture](../../docs/architecture.md) for ownership and native integration limitations.

Typography uses the native system interface font. Conversation text uses a 13px SFMono-Regular/Menlo/Consolas stack; code and diffs retain monospace highlighting. Project and session rows use compact spacing.

Both Settings buttons open one dedicated view with General, Accounts, Models, Permissions, Sessions, Shortcuts, and Advanced sections. Appearance, permissions, and send shortcuts use themed, keyboard-accessible menus; switches use the same visual style. Future options are explicitly labeled **Coming soon**. Enter sends a prompt and Shift+Enter inserts a newline; Settings can change submission to Cmd/Ctrl+Enter. Pointer clicks have no focus outline, while keyboard navigation retains a focus indicator.

Icons are the regular-weight SVGs from `@phosphor-icons/core`, pinned to 2.1.1. The selected assets and MIT license are included locally in `ui/icons` so Electron and the browser preview work offline. Regenerate them with `npm run icons --workspace apps/desktop`.

Both sidebars can be collapsed using the title-bar buttons or resized by dragging their dividers. Focus a divider and use arrow keys to resize, or Home/End to choose its minimum/maximum width. Widths and visibility persist; narrow windows clamp widths to preserve space for the conversation. The inspector offers Timeline, Changes, Files, and Code tabs. Its history control defaults to the working tree; Files opens full file contents in Code, while Changes shows the selected file's diff. Before/after views retain deleted files. The working-tree view reads saved files directly, including before the first prompt. Search filters the file list. Historical selections use recorded Git snapshots. Unsaved editor buffers are not visible. Line-number tooltips identify their originating snapshot; click a historical line number to inspect that checkpoint.

## Run

Use Node 22.19 or newer. From the repository root:

```sh
npm install --ignore-scripts
# Run this reviewed lifecycle script only after explicitly authorizing it:
node node_modules/electron/install.js
npm run desktop
```

`RELAY_NODE_PATH` selects the Node executable for the agent child process. On this machine the default Volta Node is too old; use `RELAY_NODE_PATH=/opt/homebrew/bin/node npm run desktop`. The development launcher bundles only the Electron main/preload entry points into ignored `.runtime/` files; application modules execute from source and resolve public installed runtime dependencies through installed npm dependencies.

`RELAY_DATA_DIR` optionally selects an isolated data directory for desktop QA. Normal launches store data under the OS application-data directory's `Relay` folder.

For a browser-only design preview: `npm run preview --workspace apps/desktop` and open `http://127.0.0.1:4318`. The preview cannot access folders or providers.

## Build the macOS application

Run `npm run build:desktop` with Node >=22.19 and an already installed Electron binary.
It creates `dist/relay-desktop-0.0.3-darwin-<architecture>/Relay Desktop.app`, using the
[standard Electron bundle layout](https://www.electronjs.org/docs/latest/tutorial/application-distribution).
The bundle includes its UI, core source, production npm dependencies, and official Node
26.0.0 binary verified against the release SHA-256 manifest. Dependency installation
uses `npm ci --omit=dev --ignore-scripts`; no dependency lifecycle scripts run.

The app launches directly from Finder and retains the normal `Relay` application-data
directory. Codex still requires its installed CLI; Claude's native SDK executable is
included in production dependencies. `RELAY_CODEX_PATH` and `RELAY_NODE_PATH` remain
available as overrides. The macOS bundle has an ad-hoc local signature. Public
distribution requires Developer ID signing and Apple notarization. This command
currently builds only for the host macOS architecture.

## Accounts and sessions

The composer has separate account and model dropdowns. The account dropdown shows provider labels, fallback order, remaining usage, and connection/management actions. Repeated Codex/Claude logins for the same provider identity reuse one account entry. Previously saved duplicates merge on startup when native metadata can identify them; profile directories and their discoverable sessions are retained. Different identities remain separate accounts for fallback.

Click the model name to search authenticated models grouped by provider, with each model ID shown once per provider. Search accepts account names, model names, IDs, and descriptions. Selecting a model keeps the current account when its catalog supports it; otherwise it chooses the first eligible account in fallback order. Unavailable profiles show their own status without hiding other accounts. Pi uses the published `ModelRuntime` catalog. Codex uses native App Server `account/read` and paginated `model/list`; Relay does not copy or refresh Codex credentials through pi. Claude uses the Agent SDK's `supportedModels()` and `accountInfo()` control requests with an empty input stream; discovery sends no model prompt and times out after 20 seconds. Model choices are validated again when selected, recorded in the conversation, and saved per session and per account. Switching accounts restores that account's selection. Stop a running request before changing its model.

Usage meters show provider-reported **remaining percentages**, reset times, and the last check time, rather than estimated token counts. Five-hour and weekly windows appear when available, including model-specific buckets. Codex Pro variants display **No 5-hour limit** and omit that meter; Standard Business retains its reported windows, following [OpenAI's pricing documentation](https://learn.chatgpt.com/docs/pricing). API-key accounts have no subscription meter. Missing data remains unavailable and failed refreshes clear previous percentages. Reset times do not imply a refill until confirmed by the provider.

Usage loads for the active account on startup and after a run, and refreshes every minute while visible. Opening account controls also checks other profiles; the refresh button bypasses the one-minute cache. Reads are coalesced per profile and time out after 22 seconds without blocking model selection. Codex uses the [app-server account rate-limit API](https://developers.openai.com/codex/app-server/) against the selected native profile. This requires an installed Codex CLI: Relay checks `RELAY_CODEX_PATH`, the standalone `~/.local/bin/codex` installation, then PATH. Native Codex owns credential refresh. Claude uses the pinned Agent SDK's experimental usage metadata method with transcript scanning disabled. Neither reader sends a model prompt; unsupported CLI/SDK behavior produces an unavailable meter without interrupting the session.

**Accounts** has **Connected**, **Add account**, and **Existing profile** tabs. Connected accounts can be selected, edited, checked for credential metadata, and moved earlier or later in fallback order. A successful credential check does not prove remaining quota or that a token has not been revoked. Existing profiles are checked before saving. **Create an account** opens the provider's official signup/login page; after registration, return to Relay and use **Sign in** to authorize the new account. Relay does not maintain a separate registration service.

In **Accounts**, enter a display name and choose **Sign in with Codex** or **Sign in with Claude**. Codex offers official browser (`codex login`) or device (`codex login --device-auth`) authorization. The former pi manual redirect fallback has no verified native equivalent and remains a preservation gap; use device authorization when a browser callback is unavailable. Claude launches the official SDK-bundled `claude auth login --claudeai` flow. Complete authorization in your system browser; Relay saves the account automatically and selects it when the current session has no account. Repeat to add separate subscriptions. Cancel or close Accounts to stop an unfinished login. Sign-in expires after 15 minutes. Failed/cancelled attempts remove only their newly created profile directory.

Managed credentials live in isolated provider profiles under `userData/sessions/accounts`, outside the renderer. Claude may use its OS credential store. Passwords are entered on provider pages, never in Relay. Existing-profile connection remains available under **Connect an existing profile**.

Open a project through the themed folder browser: enter a path, navigate folders, filter with search, and select **Open folder**. **Open in Finder** is an optional bottom action. Then use **Accounts** to connect authenticated profiles. Claude uses the Claude Agent SDK; Pi uses published packages for its loop, credentials, model runtime, and coding tools. For Claude, point to a Claude config directory. **Use Codex login** connects `~/.codex` directly for native App Server execution. Account catalogs and usage use the native Codex profile without credential copying. A former pi-only Codex profile must be authenticated in native Codex before App Server can use it. **Use Pi profile** connects a Pi directory containing `auth.json` and optional `models.json`. **Load profile models** supplies available model IDs and stored-auth metadata. Account rows support editing and changing fallback order. A blank directory uses the engine's default profile. Separate accounts need separately authenticated directories; Relay does not log accounts out or copy credentials. Explicit Claude profile selection suppresses inherited API-key/token overrides.

Select an account in the composer. With **Auto switch** enabled, confirmed subscription/quota exhaustion tries remaining profiles in configuration order, once each. Each fallback's credentials and selected model are checked first; unavailable candidates are skipped with an inline explanation. Model choices remain independent across accounts and providers. Claude's structured subscription rejections also trigger recovery if the SDK stream terminates without a final result. Allowed overage warnings alone do not trigger rotation. Generic HTTP 429s, authentication failures, timeouts, and context-window errors do not trigger rotation. One run is allowed across the desktop so concurrent sessions cannot misattribute project edits. You can browse another session while a run continues, then stop the active run with **Stop run**. Switching the active account during a run interrupts the old engine and continues with the new account only after settlement. Unknown execution stops continuation and requires reconciliation. Stop and disabling automatic switching remain authoritative during fallback discovery. Accounts are retried on later runs; Relay does not infer a quota reset time.

Relay owns the durable public conversation/action ledger and multiple native records per session. Native transcripts and compaction belong to their backends. Switching accounts/models resumes or creates a matching native record and supplies missing public conversation, completed outcomes, artifacts, and task state through a bounded handoff. This preserves Relay identity and workspace, not hidden state or foreign provider threads. Completed effects are descriptive context, not executable tool requests. Unknown effects quarantine the workspace until explicit verification/reconciliation; settled account recovery sends a continuation request. The model still decides future actions.

Credentials remain in each engine's managed or existing profile. Relay metadata/transcripts are local files under Electron's `userData/sessions` directory, with restrictive file modes. Claude SDK permission requests and Pi tools use a themed approval dialog. Choose **Allow once**, **Allow for this run**, or **Deny**. Per-run approval resets on a new request, cancellation, or manual account selection; it is never saved as a permanent bypass. Startup may read active-account usage metadata; offline tests make no provider requests.

The composer and Settings expose a saved per-session permission mode. **Ask** presents native approvals where supported and uses tool hooks for Claude/pi. **Allow edits** permits known read and file-edit tools while shell and unknown tools require approval. Claude uses `PreToolUse` on every call, including calls its native policy would auto-approve. Codex retains native sandbox and approval semantics, which do not expose equivalent dialogs for every action. **Read only** permits supported reads within the project, including symlink containment checks, and denies writes and shell execution. Changes are disabled during an active run or file save. Snapshot reviews retain stricter runtime permissions. Tool hooks and dialogs are not OS isolation boundaries for trusted extensions, project hooks, or remote MCP servers.

## Automatic Codex and Claude sessions

Local Codex and Claude sessions appear automatically under their projects at launch. Relay refreshes discovery every minute and when its window regains focus, including sessions in saved native Codex and Claude account profiles. Search the sidebar by title, project, provider, or session ID. Discovery reads lightweight metadata; opening a session loads its full supported history into the persistent shared Relay store. Concurrent opens are serialized and duplicate provider/session IDs resolve to one copy. New and removed source sessions update the catalog; an already opened Relay copy is preserved, including its continuations.

Session titles prefer Codex's native `session_index.jsonl` names and Claude SDK metadata, then the first meaningful user prompt. Injected instructions and environment blocks never become fallback titles. Project groups collapse; rows show the provider and date, and recent rows show the provider and project. Messages render Markdown and highlighted fenced code. The chat omits injected context, compaction summaries, analysis, and import notices; structured approval-answer wrappers display their actual answer. Ordinary code, XML, and JSON examples remain visible. Claude text/tool blocks keep their source order. Display repairs apply to existing imported copies while preserving the saved history and Relay continuations.

Discovery excludes internal Codex guardian-review and subagent threads. Previously imported internal copies are hidden from the public library without deleting their stored history. Older ordinary imports recover native message channels for display filtering.

**Import sessions** remains available for optional custom sources and previewing before opening. Select Codex or Claude, then search local conversations by title, project, or session ID. Default discovery reads `CODEX_HOME` / `~/.codex` or `CLAUDE_CONFIG_DIR` / `~/.claude`; custom profile directories, sessions folders, and individual JSONL files are supported. Saved account directories are suggested in the source input. Select a conversation to preview messages and tool results, optionally choose its current project folder, then import it. Already imported sessions open their existing Relay copy without overwriting new Relay work.

The imported copy is a normal persistent Relay session available to every connected account and provider. Original transcripts stay unchanged. Claude's existing Agent SDK `getSessionInfo()` and `getSessionMessages()` APIs read a bounded, read-only transcript store and follow the active conversation branch. Codex rollout records supply messages, function/custom-tool calls, outputs, context summaries, and rollback events; duplicate event-message mirrors and private reasoning are excluded. Completed tool results remain in the shared ledger and unfinished calls are marked as having an unknown outcome. No provider request or tool execution occurs during discovery or import.

Imported sessions continue through Relay's existing shared-context bridge in a new provider conversation; this is conversation transfer, not native-session takeover or ongoing synchronization. Attachments, provider settings/permissions, subagent transcripts, and historical file snapshots are not copied. A preview uses the same chat renderer and shows at most 80 visible actions; import retains the complete supported conversation. Existing Git/Timeline refs remain accessible through Project history. Stop an active source session before importing to capture its latest complete state.

An unavailable original project does not prevent reading an imported conversation. Use **Link folder** in its header before prompting to select the current project location. New snapshots begin when Relay runs tools with timeline enabled. Imports require no connected account for browsing; connect/select an account to continue. Very long histories remain subject to the existing desktop context-management limit.

Discovery caches metadata by file modification time and size, reports progress and warnings in the sidebar, and treats absent default profiles as empty. Unlinked conversations remain readable and can be linked to a folder before prompting. Discovery skips nested symlinks and subagent directories, reads at most 2,000 candidate JSONL files / 20,000 directory entries to depth six, and reports limits or unreadable records. Select a narrower source folder when needed. A full transcript is limited to 128 MiB. Malformed complete JSON records fail visibly; an incomplete final record is skipped with a warning.

## Timeline and reviews

Timeline is optional and off by default. In a supported Git project, **Import timeline** imports recorded changes belonging to the selected session and opens **This session**. It reads the exact `refs/relay-timeline/<Relay-session-id>` and, for imported Codex conversations, `refs/codex-timeline/<native-session-id>` refs. Other session refs and ordinary repository commits are excluded. Imported checkpoints persist without duplicating existing snapshots. Sessions without matching saved checkpoints show that no recorded changes are available; Relay does not reconstruct historical file versions from chat. Imports read up to 2,001 recorded entries and show a notice when truncated.

Import and future checkpoint capture are enabled per session. **This session** displays saved file-change checkpoints and their reviews; tool calls, account switches, and errors remain available in the conversation. **Disable timeline** stops capture for that session without deleting recorded snapshots. Older saved project opt-ins are retained for their existing sessions when loaded; new sessions start with timeline disabled. Non-Git, unlinked, and unavailable folders show a simple unsupported state in the Timeline tab; capture failures never append Git errors to chat. Older timeline-error records are hidden for display while their ledger entries remain intact. Chat, tools, Files, Code, and working-tree Changes remain independent of this option.

The explorer adapts the project-history and full-context behavior from the local `timeline-npm` and Neovim `diff-display` projects. **Timeline → Project history** reads ordinary Git commits plus existing `refs/codex-timeline/*` and `refs/relay-timeline/*` recordings. Recorded tree matches group ordered changes under commits; unmatched later recordings appear under **Uncommitted changes**. History refreshes while this view is open. Session activity remains available under **This session**. This integration reads existing Timeline refs; it does not install external hooks.

**Search diffs** searches literal added and removed text, across changed files or the selected file. **Search code** includes unchanged source and removed lines. Results identify the before/after line and open **Changes in context**, which preserves the entire file and interleaves deletions with additions. Searches are case-insensitive and bounded to 200 matching lines, 500 files, 8 MiB of read source, and approximately five seconds; limit/skipped-file notices appear in the search panel. Large single Git reads can exceed the time budget. Project history currently reads up to 2,001 entries per source. File-order annotations for imported history are limited to the most recent 100 recorded events in a group.

Files and snapshot browsing use collapsible directory trees with path search. Expanded snapshots show changed files by default; **All files** exposes the complete tree. **Previous/Next** navigates snapshots. File badges and full-context line-origin buttons identify recorded changes. Saved review notes and AI reviews are visible on their snapshot.

**Edit working file** opens the current UTF-8 source in an editor with syntax-highlighted Preview, explicit Save, and unsaved-edit protection when closing the editor. Saves preserve line endings and permissions, reject stale contents, refuse symlinks/hard links and files outside the project, and record before/after checkpoints when timeline is enabled and Git is available. Stop an active agent run before saving. Historical files are never overwritten or restored automatically; a deleted working file must be recreated outside this editor. The editor supports existing text files up to 2 MiB. Closing the entire app does not persist unsaved editor drafts.

The middle conversation groups each prompt's tool calls, checkpoints, and intermediate progress notes under one initially collapsed work row. The final assistant reply remains visible. Expanding the row reveals ordered command/file summaries, running/completed/failed states, and completion durations; individual inputs and readable outputs render only when expanded. Public pi `tool_execution_update`, Claude `tool_progress`/hooks, and Codex App Server item events feed the application event ledger. Recorded file changes link to their historical snapshot directly from the conversation. Account/model changes and errors also appear inline. Expanded state survives streamed updates.

Projects must be Git repositories for code snapshots. Hidden `refs/relay-timeline/<session-id>` commits capture the entire repository through a temporary index, without touching the user's index, branch, HEAD, or working files. Nonignored untracked files and deletions are included; ignored files are excluded. Tool notifications and debounced live filesystem observations produce chronological snapshots. Native tool notifications reach the desktop asynchronously, so an exact snapshot before each native tool is not guaranteed. A snapshot can contain effects of overlapping tools or external edits. This compatibility cost remains a migration gate for stronger boundary guarantees.

**Inspect codebase** opens the full historical tree. Changed/deleted files appear first. Switch between the complete before/after file and its diff, with line numbers. Review notes attach to the snapshot and can include `file:line` references. **AI review** runs the selected account against a temporary export of the entire immutable snapshot, with supported read-only runtime policies. Trusted hooks and external servers remain outside those tool-policy guarantees. The review is streamed and persisted against its original snapshot. The temporary export is removed after verified settlement; uncertain execution preserves it and records its path for inspection. Reviews use separate linked native conversations and do not replace the coding session's native mappings. Git blame tracks the origin checkpoint of retained lines across successive edits.

A file created and deleted in separate tool calls is retained. A change made and undone entirely inside one shell command between observations may not be captured. Very large files can exceed the current 32 MiB Git output limit. Git snapshots remain until their refs are removed explicitly; Relay does not garbage-collect them.

## Verification

Run `npm run check` and `./test.sh` from the root. The offline tests cover the shared service,
native adapter contracts, account/login metadata, session imports, permissions, timeline,
workspace editing, and renderer diffs. They use fake backends and temporary repositories.

Run `node --test test/code-view.test.mjs` from this directory for renderer diff tests.
See [core validation](../../packages/core/README.md#validation) and the
[architecture limitations](../../docs/architecture.md#validation-and-limitations).
Offline checks do not prove live native inference, Electron rendering, or subscription fallback.
